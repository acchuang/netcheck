Three Enhancement Approaches for NetCheck

Maintainability-first, each with different depth and commitment

Approach A — Quick Wins Bundle
SHIPPED IN 2-3 DAYS
✅ GitHub Actions CI/CD (lint, typecheck, test, deploy)
✅ ESLint + Prettier config
✅ Unified error handling & logging
✅ Component extraction (split monolithic *-ui.ts files)
✅ Dashboard overview tab (summary of all tests)
✅ Better mobile nav

Pros

  • Immediate developer velocity boost
  • Low risk, no breaking changes
  • CI catches bugs before deploy

Cons

  • Doesn't address deeper architecture
  • New features still hard to add
  • UI still vanilla DOM manipulation
Approach B — Architecture Refresh
SHIPPED IN 2-3 WEEKS
🏗️ Lightweight reactive layer (Preact/Lit)
🏗️ Component-based architecture
🏗️ Shared state management
🏗️ Design system tokens & CSS variables
🏗️ Comprehensive test suite
🏗️ Dashboard + new features

Pros

  • Massive DX improvement
  • New features become trivial
  • Tests give confidence to refactor

Cons

  • Significant rewrite effort
  • Risk of regressions mid-migration
  • Bundle size increase
Approach C — Incremental Modernization (Recommended)
PHASED OVER 4-6 WEEKS
Phase 1 — Foundation: CI/CD, linting, component extraction, shared state, design tokens
Phase 2 — UX Layer: Dashboard overview, animated transitions, improved mobile, accessibility audit
Phase 3 — New Features: TLS cert inspector, IPv6 check, connection history timeline, test comparison
Phase 4 — Polish: E2E tests, performance budget, PWA improvements, SEO enhancements

Pros

  • Ships value every phase
  • Safe migration path — always working
  • Each phase builds on the last
  • Can stop at any phase

Cons

  • Longer total timeline
  • Requires discipline to not skip phases

Key Insight from Code Review

The biggest maintainability bottleneck: Each tab's *-ui.ts file (dns-ui.ts ≈ 400 lines, speed-ui.ts ≈ 500 lines, adblock-ui.ts ≈ 300 lines) mixes DOM construction, event handling, data fetching, and rendering logic in monolithic functions.

No shared state: Results from one tab can't inform another (e.g., DNS results can't auto-suggest which speed server to test against).

No CI/CD: No GitHub Actions, no automated testing on push, no linting in the pipeline — bugs can ship silently.
